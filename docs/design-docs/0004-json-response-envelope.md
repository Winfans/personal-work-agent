# 0004 — 普通 JSON 响应结构

- 状态：已采纳
- 日期：2026-10-16

## 背景

健康检查和笔记接口原本直接返回各自的数据，错误沿用 FastAPI 的 `detail` 格式。客户端需要分别处理这些结构，新增普通 JSON 接口时也缺少统一约定。

## 决策

业务接口的普通 JSON 响应统一为 `{"code": number, "message": string, "data": value}`。成功时 `code` 为 `0`、`message` 为 `OK`；失败时 `code` 与 HTTP 错误状态码一致、`data` 为 `null`。删除成功使用 HTTP 200 和 `data: null`，以便返回完整结构。

NDJSON 成功流继续使用按行分隔的事件格式。流开始前发生的 HTTP 错误采用统一 JSON 结构；流开始后的错误使用 `error` 事件。OpenAPI 文档响应保持标准格式。

## 影响

- 后端响应模型和客户端解析需要同步更新。
- 不依赖 `detail` 或空的 204 响应体处理错误和删除操作。
- HTTP 状态仍表达成功或失败；`code` 提供稳定的业务响应字段。

## 代理实施提示

新增普通 JSON 路由时使用共享响应模型；同步更新消费者、测试和文档。不要把 NDJSON 事件包进此结构。
