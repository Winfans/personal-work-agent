# 核心原则

这些原则旨在让代理可靠执行工作，并方便后续维护。

1. **仓库记录项目知识。** 重要意图、约束和决策应在仓库内可查。
2. **给代理地图。** 从简短入口开始，按任务需要进入更深层文档。
3. **在边界验证数据。** 外部请求、服务商响应、数据库输入和流事件都应有明确结构。
4. **逐步将约束变成自动检查。** 文字先说明规则；测试、类型、检查器和脚本提供更强保障。
5. **让运行结果可观察。** 编译通过不足以证明正确，还需检查用户行为、日志和失败情形。
6. **优先清晰的组合。** 明确模块及稳定工具比本地难以理解的隐式机制更易维护。
7. **人决定方向，代理负责执行。** 人确定优先级和关键产品取舍；代理在授权范围内实现并提供证据。
8. **缩短反馈周期。** 将反复出现的故障和评审意见转为仓库内持续有效的改进。
9. **以证据判断完成。** 说明实际运行了哪些检查、观察到什么，以及哪些仍未验证。
10. **持续清理漂移。** 尽早记录并处理小范围技术债，避免不良模式扩散。
