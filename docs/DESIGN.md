# 工程设计

## 设计目标

- 让目录和导入关系清楚呈现领域边界。
- 明确外部数据的结构并验证。
- 将外部服务和持久化细节封装在后端服务层。
- 优先采用可直接测试的小模块，减少隐式框架行为。
- 跨 UI 和后端的变更应保持用户可见契约。

## 跨组件变更检查清单

1. 找出受影响的领域、公共契约、数据和失败路径。
2. 阅读相关产品规格、设计记录，以及可靠性、安全文档。
3. 工作跨越多个边界或会话时，建立执行计划。
4. 实施前定义可观察的验收标准。
5. 确定代理如何复现、检查及验证结果。
6. 对反复出现的重要约束增加自动化检查。

## 当前约定

- FastAPI 路由承担适配职责，service 承载业务行为。
- Pydantic schema 定义 HTTP 数据结构。
- 普通 JSON 响应使用共享的 `ApiResponse`；流开始前的错误遵循同一结构。
- SQLAlchemy model 和 session 管理持久化。
- 渲染进程 API 模块负责 fetch 和流解析。
- React 组件管理视图及交互状态。
- 默认测试使用模拟对象替代外部调用。

## 设计欠账

仓库已记录边界，但还没有自动检查导入关系或架构方向。增加此类检查前，应依据实际导入图明确允许的依赖边；宽泛而不准确的检查器会带来错误的安全感。
