# 质量评估

这是持续维护的缺口地图。以下等级依据 2026-10-16 仓库中可见的证据，不能代替运行验证。

| 领域 | 等级 | 当前证据 | 最重要的缺口 |
| --- | --- | --- | --- |
| 后端契约 | B | Pydantic schema 和 API 测试 | 异常及不规范服务商响应覆盖不足 |
| Agent 流式处理 | B- | service 与路由测试覆盖正常路径 | 取消、分块边界、超时和错误路径测试 |
| 笔记 | C+ | 已有 CRUD 代码和隔离的 API 测试 | MySQL 与 Electron 真实流程验证 |
| 前端 | C+ | 类型检查与生产构建通过 | 自动交互和无障碍测试 |
| 架构 | C | 边界已有文档 | 自动验证依赖方向 |
| 安全与隐私 | C | 后端保存凭证的边界明确 | 脱敏策略、依赖安全检查和威胁模型 |
| 可靠性 | C- | 部分超时及错误提示已实现 | 重试、降级、依赖健康和恢复测试 |
| 可观测性 | D | 仅有基础应用日志 | 结构化日志、关联 ID、指标、链路及可查询能力 |
| 交付 | D | 有本地构建命令 | CI、统一验证入口、打包及发布证据 |
| 文档 | B- | 知识库可导航 | 自动检查链接、时效及内容漂移 |

## 调整等级的规则

提高等级需要仓库内可见的证据，例如代码、测试、检查命令、派生文件或实际运行记录。行为或文档出现漂移时，应下调等级。
