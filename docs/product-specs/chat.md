# 聊天与知识检索

## 用户目标

用户发送对话后，及时看到处理状态和逐步生成的回答。涉及私有或项目知识的问题可以使用已配置的知识库。

## 行为

- 回答流式生成期间，发送操作不可用。
- 新对话清空当前展示状态，并取消正在进行的请求；发送第一条消息时创建 MySQL 会话。
- 侧栏展示多个历史会话，点击后可恢复消息并继续聊天。首次只加载最近 50 条，用户可按需加载更早消息；会话列表每次加载 30 条。
- 用户消息在服务端开始处理时保存；助手回答完成后保存。失败时保留用户消息，未完成回答不入库。
- 路由结果显示普通聊天或知识库聊天。
- RAG 在生成前报告检索结果数量。
- `delta` 事件的文本逐步呈现。
- 连接或服务商失败时显示错误，UI 不应崩溃。

## 契约

`POST /agent/run` 接受消息历史或兼容的单条消息。事件流遵循[设计记录 0002](../design-docs/0002-agent-stream-protocol.md)。`/chat/text` 仍与同一 Agent 行为兼容。

聊天历史使用 `/api/v1/conversations` 的创建、列表、详情、消息分页接口；`POST /api/v1/conversations/{id}/run` 接收单条用户消息并持久化本轮对话，同时返回同样的 NDJSON 事件流。旧流式接口不隐式保存聊天记录。完整消息历史存库；生成上下文最多使用最近 100 条消息。

流开始前若请求校验或服务配置失败，接口返回统一 JSON 错误结构；流开始后的失败继续用 `error` 事件报告。
