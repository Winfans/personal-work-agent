# 可靠性

## 关键用户流程

1. 配置有效时后端正常启动。
2. 普通聊天完成路由及流式回答。
3. RAG 聊天完成检索、报告来源并流式回答。
4. 笔记 CRUD 能持久保存并重新加载。
5. 取消请求或依赖故障后，UI 仍可继续使用。

## 当前措施

- 外部请求使用明确的 HTTP 客户端；Jev 的超时可配置，RAG 有固定超时。
- 响应开始后的流式失败会转成 `error` 事件。
- SQLAlchemy 使用 `pool_pre_ping`。
- 测试通过模拟对象和依赖覆盖隔离外部服务。

## 需要的证据

- 验证确定性行为的单元及 API 检查。
- MySQL 和各已配置外部服务的集成检查。
- 用户可见状态的桌面端交互检查。
- 破坏性或影响持久化的变更所需的恢复证据。

## 已知缺口

- 缺少统一的重试、退避和降级策略。
- 数据库初始化失败可能阻止整个后端启动。
- 健康接口只报告进程状态，未检查依赖是否就绪。
- 缺少 SLO、指标、链路、关联 ID 和自动化运行流程探针。
- 笔记尚无有记录的备份与恢复测试。

在得到验证证据前，不应将上述能力描述为已具备。
