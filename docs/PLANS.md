# 计划编写规则

局部的小改动可以只在当前会话中规划。跨组件、风险较高、存在关键未知、需要人工决策，或可能跨会话继续的工作，应把执行计划纳入仓库。

计划放在 `exec-plans/active/`，按 `exec-plans/TEMPLATE.md` 编写，应让新接手的代理能够独立恢复上下文。执行过程中持续维护进度和决策记录，只写实际观察到的证据。

所有验收标准均有证据支持，或由负责人明确豁免时，计划才可完成。随后更新长期有效的架构、产品和设计文档，再将计划移至 `exec-plans/completed/`。暂未解决的技术债应进入 `exec-plans/tech-debt-tracker.md`。
